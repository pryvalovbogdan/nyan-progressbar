# i18n Rules

## All visible text must live in translations

Every string that appears in the UI **must** come from the `Dictionary` (via `dict.*`). Never hardcode human-readable text directly in a component.

### What this means in practice

- Every piece of visible text — headings, paragraphs, labels, button text, list items, link text, placeholder text — must have a corresponding key in `src/i18n/en.json` (and all other locale files).
- When you add a new key to `en.json`, add the **same key** to every other locale file (`de`, `es`, `fr`, `id`, `pl`, `pt`, `tl`, `uk`, `vi`), translated into each locale's language. Never copy English text into a non-English locale file.
- Views receive `dict: Dictionary` as a prop. Features and widgets that render text must also receive the relevant dictionary slice as a prop (or accept the full dict).

### What is exempt

- URLs, `href` values, `src` paths — these are not user-facing text.
- ARIA attributes that are purely technical (e.g. `aria-hidden="true"`).
- HTML entity escapes like `&quot;` or `&apos;` used for JSX safety — but the underlying string the user sees must still come from `dict`.
- Code examples or technical identifiers inside `<code>` / `<pre>` blocks where the value is inherently language-independent.

### How to add new text

1. Add the key(s) to `src/i18n/en.json` under the relevant section.
2. Add the same key(s) to **all** other locale files, each translated into that locale's language.
3. Read the key from `dict` in the component — never from a local constant string.

### Wrong

```tsx
<h2>Privacy Policy</h2>
<p>The extension runs entirely in your browser and does not collect data.</p>
```

### Right

```tsx
<h2>{dict.privacy.heading}</h2>
<p>{dict.privacy.body}</p>
```
